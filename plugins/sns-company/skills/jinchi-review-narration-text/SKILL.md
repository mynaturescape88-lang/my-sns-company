# jinchi-review-narration-text（工程4 音声用テキストの実施前レビュー）

人智の外側 長尺パイプラインの **工程4（ナレーション音声の生成）** で、TTSを撃つ前に当てる実施前ゲート。無料枠を無駄撃ちしないため、音声用テキスト・音声の指定・設定値が完璧に確定していることを確認し、全passして初めてTTSを撃つ。親 `jinchi-longform` の工程4手順2から発動。完成音声のレビューは別skill `jinchi-review-narration`。

## 読むのは3つだけ（混在禁止・token効率）
- ① 本skill内の観点リスト＝工程4実施前の合格ライン
- ② `.company/pm/review-baseline.md`＝全レビュー普遍の項目
- ③ `.company/sns_accounts/youtube_ainsight.md`＝人智の外側の戦略・トーン前提の照合先

## フロー（発動＝この順で全実行・fail-closed）
- ① 本skillの観点を音声用テキスト（章別txt）に1つずつ照合し、pass/failを判定する
- ② `pm/review-baseline.md` の各項目を1つずつ照合する
- ③ fail-closed＝1つでもfailならTTSを撃たず修正して①へ戻る
- ④ 全passのみTTS実行へ進める

## 工程4実施前の観点（1つずつ照合）
- [ ] **音声用テキストが、1ファイル1章・改行を字幕行とする章別txt形式で確定していること**
- [ ] **読点が可読性・発話テンポを損なう過剰な連続になっていないこと**
- [ ] **既知の誤読対策の読みかな開きが、対象章の全該当語に反映されていること**
- [ ] **「間」が意図どおりで、不要な無音や欠落した間が無いこと**
- [ ] **章記号「起1・承2」等の禁止語が音声用テキストに残っていないこと**
- [ ] **数値が桁を誤読しない表記になっていること**
- [ ] **各ナレ文章のトーン指定文が、その本文と語・言い回しで重複していないこと**
- [ ] **読み崩れ・数値桁・禁止語の残存が機械走査で0件であること**
- [ ] **音声の声とスタイル指示文が確定していること**
- [ ] **正規化などの設定値がRUNBOOKの値で確定していること**
- [ ] **当日撃つ章数が無料枠の1日上限に収まっていること**
- [ ] **上限を超える見込みのときは実施前にオーナーへ報告していること**

## 原則
- レビューに出す成果物は、既知の改善余地がゼロで自分で直せる弱点が残っていないこと。
- 要件未達は自分で不合格にして作り直すこと。
- passした成果物だけを提示すること。
