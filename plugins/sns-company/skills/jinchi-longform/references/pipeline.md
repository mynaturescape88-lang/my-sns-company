## 4. ナレーション（Gemini TTS・無料）＝1章1リクエスト方式
- **確立手法＝台帳生成器が出力した音声用テキスト（`<topic>-narration-clean/` の章別txt・1ファイル=1章）を「1章=1リクエスト」でTTS**（`\n\n`段落分割はしない＝章内の声の揺れをゼロにする）。参照実装＝人智共通のナレ生成ベース（cutoff/loop検出＋端無音トリム＋loudnorm を内包。**是正なしのブラインド自動リトライ＝best-of-Nは持たない＝検出時もmp3は保存し、採用しないまま是正してからリトライする**）。ベースの場所・実行値はRUNBOOK。汎用スクリプトなら `scripts/gemini_tts.py tts --file <章txt> --whole --voice Charon --style "落ち着いた低い声で、ミステリー番組のナレーターのように。" --output ...` を**章ごとに**回す（`--whole`＝全文1リクエスト）。
- ⚠️無料枠 10回/日・JST16時頃リセット。429で止まったら枠回復後にresume（生成済みの章はスキップ）。**撃つ前に音声用テキスト・音声の指定・設定値を完璧に確定させる（実施前チェック＝`jinchi-review-narration-text`）＝準備が完成していればcooldownは不要**。
- ⚠️**失敗テイク（cutoff/loop等）を検出したら、そのmp3を採用せず原因を究明し、入力・style・設定を是正してからリトライする（是正後のリトライは自走可）**。**是正なしのブラインド再撃ち（自動リトライ・章内best-of-N）はしない**＝無料枠の無駄撃ちを防ぐ。是正しても直らず真因不明が続く場合のみオーナーへ報告する。
- ⚠️実施前チェック＝当日の想定利用回数（撃つ予定の章数）が1日上限（10回）を超える場合は、実施前にオーナーへ超過見込みを報告する。
- ⚠️**音量のばらつきは章境界にだけ出る**（1章＝1リクエストなので章内は揺れなし）→各章を端の無音のみトリム＋`loudnorm I=-17:TP=-1.5:LRA=11` で正規化してから連結（章内の自然な「間」は保持）。
- ⚠️**全再生成しない**（他章の良いテンポまで変わる）。直すのは音量正規化＋**該当章のみ**再生成。**誤読は章再生成せず文スプライス**（`splice_sentence.py`・無音境界）。
- ⚠️cutoff（喋り止め後ずっと無音）/loop（同一文反復）は**総尺でなく実発話尺＝字/秒＋whisper文字カバレッジ**で検出（raw総尺は末尾無音に騙される）。
- 尺目安＝日本語100字≒25秒／2000字≒5〜6分。

## 8. ★Whisper字幕同期（最重要・無料）
- `.venv/bin/python scripts/nazca4k_whisper.py`（または `align_captions.py`）→ 行ごとの実発話時刻 → アセンブラの行アンカーへ。文字数比だと実発話と最大±5秒ズレる。**align後に再ビルド**。
- ⚠️**この環境のffmpeg（brew 8.x）はsubtitles/drawtextフィルタ非搭載**→字幕/タイトル/ブランドは**PILでPNG生成しoverlayで焼く**方式（`build_nazca_4k.py`に内蔵）。
- **★行頭アンカーは「読み形」に寄せて照合する（恒久・2026-07-17 第4弾で確立／実装正本＝`scripts/build_aivuln_4k.py`）**：clean台本は**TTS読み表記**（AI→エーアイ 等＝`<topic>_prep_tts_text.py` の `REPL` で変換済）だが、Whisper認識は**綴り**（AI）で返る。この不一致で `find()` が外れた行は **char-ratio補間へ落ち、実発話の「間」を無視した比例配置＝1.0〜1.6s早い字幕**になる（第4弾起1で実測・数値ゲートは誤PASS）。恒久対処＝アセンブラに**読み正規化レイヤ**を持たせる：
  1. `from <topic>_prep_tts_text import REPL` してWhisper側にも同じ変換を当て、**両側を読み形へ寄せて照合**（`_READ_RULES` / `_read_norm_str` / `_read_norm_pairs`）。**辞書はREPLが単一の真実源**＝将来の固有名はREPLに足せば台本・字幕・照合へ自動反映。
  2. REPLに無い**Whisper綴りゆれ**（一つ↔ひとつ／例える↔たとえる 等）は `_READ_EXTRA` で補う。
  3. 完全一致で拾えない行は **difflibの行頭probe（ratio≥0.6）** で拾い、**補間へ落とさない**（`_fuzzy_head_pos`）。
- **★glued限定の実音声スナップ**：`_speech_mask` / `_snap_to_speech` ＝直前語とのwhisper gapが **<0.08s** の「貼り付き語」だけを発話再開位置へ前進スナップする。**真正の「間」では不発**＝演出の間を潰さない。
- **この工程（字幕同期）の完了条件（この2つを満たすまで次へ進めない）**：① 章ごとに**アンカー成立＝全行／補間0**（成立率を記録）② **フレーム抽出×独立Whisperの実測で全札|Δ|<0.35s**。`jinchi_caption_sync_check.py` の median/max のPASSは**合格根拠にしない**（最寄りonsetを拾うため誤PASSする）→ 判定は `jinchi-review-caption` の観点で行う。

## 9. 全結合（OP/ED結合・章転換札・本編BGMなし）
承認済みの全章を、OP/EDと章転換札とともに stream-copy のみで連結し完成フル版にする手順（再エンコード・all再生成・映像再エンコードをしない）。

1. OP/EDの固定資産を用意する
- OP＝`op-ed/op_final_4k.mp4`、ED＝`op-ed/ed_final_4k_48k.mp4`（4Kアップスケール版）を使う。作り直さず・音量も触らない。**EDは必ず `_48k` 付きを掴む**＝48kHz版＝章mp4と同じ音声レートで `-c copy` 可（同ディレクトリに旧 `ed_final_4k.mp4`＝44.1kHz が現存し、そちらは音声レート不一致でstream-copy連結できない）。
- EDはconcat前に音声だけ48kHzへ揃える（映像はcopy）。

2. 章転換札を作る（第2章〜最終章の各直前ぶん）
- 黒画面＋章タイトル札＋ポーンSE。尺4.0s（fade in 0.4／hold 3.2／fade out 0.4）。SE＝`_shared/sfx/pon.wav` をt=0に1回鳴らしapadで4.0sへ充填。
- 札PNG＝3840×2160・純黒背景・中央寄せ／タイトル＝Zen Maru Gothic Bold 160px・トラッキング+6・色#efece8／番号＝Zen Maru Gothic Medium 64px・トラッキング+16・色#9a9490／［番号］→ギャップ72px→［タイトル］を画面中央へ／title-safe 3360px（超過は8px刻みで80pxまで縮小・改行しない）。
- 札クリップは本編章と同一パラメータ（libx264/yuv420p/30fps/crf20＋aac256k/48kHz/stereo）で書き出す。

3. 並び順に連結する
- 並び＝`OP → [黒gap] → 第1章(コールド) → [札] → 第2章 → [札] → … → [札] → 最終章 → [黒gap] → ED`。
- コールドの直前には札を置かない＝札は第2章の直前から最終章の直前まで。
- 本編BGMは載せない＝本編（章）はナレーションのみ・章別BGM/ダッキング/サイドチェインをしない。音の変化は章転換のポーンSEだけ。BGMプールは資産として保持するが本編へ載せない（BGMはOP/EDに元から入っている分だけ）。
- stream-copyで連結する。
