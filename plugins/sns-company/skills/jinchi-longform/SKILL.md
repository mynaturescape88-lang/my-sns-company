# 下記工程を順番に抜け漏れなく実施すること

## 工程1. 題材の選定・確定
**担当**：creator（題材候補の調査・提示）。題材の最終決定はオーナー。

1. 題材選定
以下の条件を**すべて満たす**テーマ候補を、Web上から3つ探し出す。

・条件（3候補とも、下記をすべて満たすこと）
- 人間には解けなかった真実を、AIが解き明かす内容である（例＝AIが世界稼働システムの脆弱性を発見／AIドローンが変えた現代戦／量子暗号解析／脳デコード）
- AIによる活躍が事実として確認できている
- 噂や予想ではなく、事実として確定している内容である
- 人の智では及ばない領域にAIが連れて行ってくれた内容だと言える
- 直近3つ前の動画と、謎の解決方法が重複していない（例＝前回が古代の文字解析なら、今回はそのテーマを避ける）
- 1年以内にニュースになった出来事である

2. オーナーへの提示
提示の前に、選定した3候補へ `pm/review-baseline.md` を照合する（レビュー）。
　failした場合：直ちに修正し、再度照合する
　全passするまでオーナーへ提示しない
全passしたら、候補3つを、テーマごとに以下の形でオーナーへ報告する。
・テーマ名／あらすじ／AIが活躍した内容／物語のオチ／いつの出来事か

3. 題材の決定
・オーナーからの質疑応答に応じる
・NGの場合：受けたFBに対応し、選定をやり直す（工程1の1へ戻る）
・OKの場合：オーナーが確定した題材のみ、工程2へ進む

## 工程2. 台本の作成
**担当**：creator

1. 企画・構成
`content-planning` を発動し、企画・起承転結の骨格＋台本生成プロンプトを作る。

2. 台本執筆
1のプロンプトを使って台本本文（ナレーション原稿）とFCログを書く。書く際は下記を遵守する。
- 中心比喩を直近3本の動画と重複させない（被れば別比喩へ差し替える）
- 前作の定型句・接続句・言い回しをそのまま流用しない（意味・役割を保って書き換え／前作台本との全文突合で検知）
- コールドオープンに3要件を含める：(a) 何についての動画か (b) 要旨予告（最後まで見ると何を知れるか） (c) 具体的な答え・オチはネタバレしない
- 新規に書いた程度・数値の一文は、既存FC済み事実とは別に個別ファクトチェックする（最良ケースの一般化・誇張になっていないか）
- 結で具体的な答え・到達点を言い切る（謎のまま終わらせない）

3. レビュー
`jinchi-review-script` を発動し、作成した台本を照合する。
　failした場合：直ちに修正し、`jinchi-review-script` を再発動する
　全passするまで工程3へ進まない

## 工程3. 章別素材台帳の作成（計画）
**担当**：creator
台帳は生成器 `gen_<topic>_ledger.py` で出力する（手編集しない）。台本は台帳を作るインプットであり、工程3以降は台帳が唯一の正本（台本を参照しない）。この工程の目的は「実現可能な計画（台帳）」を立てること。埋めることは手段であり、立てた計画が実現可能に成立していることが完了条件。実測値は後工程で更新する。

1. ベースを用意する
共通の台帳生成ベースを使う薄い題材設定を作り、この題材の設定（台本パス／出力先／章順／章タイトル／図解仕様）を渡す（ベース自体は複製・改変しない・過去題材のスクリプトもコピーしない）。使い方はRUNBOOKを読む。

2. カット計画を書く
工程2の台本を再生順のカットに分解し、生成器の `CUTS` に1カット＝1行で書く。各カットに決めるもの：
- 区分（①実写／②0cr画像・テロップ・社名カード／③図解／★合成／(間)）
- 画（何を映すか）
- VO（そのカットで読み上げるナレ逐語全文＝台本から転記。要約にしない）
- 素材ID（固有ID）
- 実写①（区分①なら●）
- 入手経路（取得元＝pipeline.md 工程5のリスト内）

3. 生成器を実行
`python <topic>/gen_<topic>_ledger.py` で台帳 `<topic>-cr-ledger.md` を出力する。尺（設計値）・本数・比率・§B/§C/§F/§I・済（⬜）は自動計算される。生成器はVO逐語を章ごとに連結し読み形へ変換して、音声用テキスト（`<topic>-narration-clean/` 章別txt）も出力する＝工程4はこれを用いる（台帳が音声用テキストの正本）。事実で埋まる列は事実で、仮値でしか埋まらない列は仮値で埋める（空欄・未確定を残さない）。実測ナレ尺・§K一次規約確認・済承認は後工程で更新する。

→ レビュー：`jinchi-review-ledger` を発動する（工程3では最上位観点＋計画段階の観点を当てる）
　failした場合：直ちに修正し、`jinchi-review-ledger` を再発動する
　全passするまで工程4へ進まない

## 工程4. ナレーション音声の生成
**担当**：creator
共通のナレ生成ベースをコピーし、この題材の設定を入れて、章ごとに音声を作り、音量をそろえて連結し、レビューを通して台帳を更新する。音声用テキストと字幕用テキストは別物（字幕＝表記のまま／音声＝読み形）。無料枠を無駄撃ちしないため、音声を作る前に音声用テキストを完璧にする。実行値（ベースの場所・声・正規化などの設定）は RUNBOOK を読む。
**この工程の完了条件＝台帳の音声素材が全章「完了」になっていること。**

1. ベースを用意する
- 共通のナレ生成ベースを使う（ベース自体は複製・改変しない＝声・音量・検出の作法はベース固定・全題材共通・変えない）
- この題材の設定（章立て・各ナレ文章のトーン指定・入出力先・各章の想定尺）だけを渡す（過去題材のスクリプトはコピーしない）
- 読み上げ用テキストは台帳から生成されたもの（工程3）を使う

2. 実施前チェック（音声用テキストを完璧にする）
→ レビュー：`jinchi-review-narration-text` を発動する
　failした場合：直ちに修正し、再発動する
　全passするまで音声を作らない

3. 音声を作り、音量をそろえて連結する（1章ずつ）
- 章ごとに音声を作り、各章の音量をそろえて連結する（章内の「間」は保持する）
- 誤読の単発は作り直さず、その文だけ差し替える

4. レビューして台帳を更新する
→ レビュー：`jinchi-review-narration` を発動する
- 問題がなければ、台帳の音声素材（各章の実測尺・ナレ音源）を「完了」に更新する
- 問題があれば、原因を追究して是正してから作り直す（是正した上での作り直しは自走してよい／是正せず同じ入力で作り直す無駄撃ちはしない）
- 原因を追究できない、または是正で解決できない問題がある場合は、オーナーへ確認する

全章の音声素材が台帳で「完了」になったら工程5へ進む。

## 工程5. 素材の取得
**担当**：creator
台帳（工程3）で計画した各カットの素材を、承認済みの取得元からのみ取得し、権利を台帳に記録し、実尺を確認して台帳を更新する。取得元リスト・取得ツールは pipeline.md §5 を読む。
**この工程の完了条件＝台帳の素材部分（各カットの取得素材・§K権利記録・実尺確認）が全て「完了」になっていること。**

1. 素材を取得する
- 台帳の各カットの素材を、承認済みの取得元からのみ取得する（承認外のサイトから引用しない）
- 使う素材はすべて合法であること（商用利用・公衆送信が可能）。合法だと確認できないものは使わない（個別の細かい判断はしない）
- ロゴ等も合法と確認できれば使ってよい。確認しきれない場合（例＝商標）は使わず、組織・企業は社名テキストカードで表す
- 動画はH.264を選別する
- ファイル名は中身と一致しないことがあるため、必ずフレームを抽出して目視で選定する
- 本物で作れるものはAI生成にしない

2. 権利を台帳に記録する
- 取得した素材ごとに、台帳§K（素材ライセンス台帳）へ取得元・一次規約・確認日・証跡を記入する（選定時点で記入する。空欄や「不明」は不可）

3. レビューして台帳を更新する
→ レビュー：`jinchi-review-figure` を発動する（取得素材の実尺が台帳の要求尺を満たすかを実測で照合する）
　failした場合：直ちに修正し、再発動する
　全passしたら、その素材を台帳で「完了」に更新し、工程6へ進む

## 工程6. 図解・合成カットの内製
**担当**：creator
台帳（工程3）で計画した図解（③）と合成（★）のカットを、無料の自作で内製し、台帳を更新する。方法（色・フォント・合成手法）は pipeline.md §6、スクリプト名・出力先は RUNBOOK を読む。
**この工程の完了条件＝台帳の図解・合成カットが全て「完了」になっていること。**

1. 図解カットを作る
- 台帳§D（図解の作図仕様）に従って各図解（③）を自作する（暗背景・金アクセント・指定フォントでブランド統一／縦中央寄せ・下部は字幕帯を空ける）
- 図解を2つ連続させない（間に実写・画像を挟む）
- 画面内に『参考：他都市』『参考：近縁種』等の注記テロップを焼かない

2. 合成カットを作る
- 台帳§D（合成の仕様）に従って各合成（★）を自作する（実素材にグローを重ねる／縁を四角く出さない・暗めの映像をベースにする）

3. レビューして台帳を更新する
→ レビュー：`jinchi-review-figure` を発動する（図解・合成が台帳の計画どおりか・実尺が要求尺を満たすかを実測で照合し、全素材の台帳との突合をここで完了する）
　failした場合：直ちに修正し、再発動する
　全passしたら台帳で「完了」に更新し、工程7へ進む

## 工程7. 章ごとの完成とオーナー確認
**担当**：creator（制作・内部レビュー）。章の最終確認はオーナー。
台帳（工程3）の計画に沿って、章を1つずつ順に完成させる。1章について下記1〜5を回し、オーナーへ提示したら、その返事を待たずに次の章の1〜5に着手する。方法はアセンブルが pipeline.md §7・字幕同期が pipeline.md §8、スクリプト名・出力先・実行値は RUNBOOK を読む。
**この工程の完了条件＝全章が台帳で「完了」（オーナー承認済み＝✅）になっていること。**

### 各章について、下記1〜5を順に回す
1. 4Kへ組み上げる
- 音声駆動でセクション尺を決め、各カットを対応ナレ行にアンカーして配置する（比例配置にしない）
- 純ナレ運用にする（語り部を出さない・案内人章を使わない）
- 字幕はPIL PNGのoverlay焼きにする（この環境はdrawtext非搭載）
- 全カットを固有素材にする（同一素材の2回目の使用も不可）
- 画像を差し替えるときは新パスにするか該当カットを削除する（同名上書きは旧画が残る）

2. 字幕を実発話に同期する
- Whisper実測で各ナレ行の発話時刻を取り、行アンカーへ反映して再ビルドする
- 台本の読み表記とWhisperの綴りが食い違う行は、読み正規化辞書へ語を足して再アンカーする（補間へ落とさない）

3. 内部レビューを全passさせる
→ レビュー：`jinchi-review-assemble` を発動する（組上げ成果物の照合）
→ レビュー：`jinchi-review-caption` を発動する（字幕同期成果物の照合）
- 加えて `references/chapter-verification-gates.md` の全項目を実測でpassさせる（提示前チェック）
- 章ゲート `.venv/bin/python scripts/<topic>_chapter_gate.py --all` を実行すること
- 章ゲートの出力末尾の「機械判定 N/13 項目 PASS（未実装＝… ／人手＝… ／他ツール＝…）」の行を、逐語のまま台帳へ記録すること
- 台帳の合否は「全項目PASS」でなく、機械判定した項目数（N/13）で書くこと
- 台帳には未実装・人手・他ツールに該当する項目番号を併記すること
- 未実装・人手・他ツールの項目は、誰が何を見て判定したかを台帳へ記録すること
　failした場合：直ちに修正し、再発動する
　全passするまでオーナーへ提示しない

4. オーナーへ最終確認を依頼する
- 書き出した章動画をChromeで表示して提示する（ダウンロードさせない）
- 提示は指摘ごとに【受けた指摘／直した内容／エビデンス（X:XX＝分:秒）】の3点セットで書く

5. オーナー承認を台帳へ反映する
- 承認された章は台帳の済を✅（完了）に更新する
- 承認された章動画のstreamhash（映像／音声）を承認マニフェストへ記録する（工程8の全結合で同一性を検証するため）
- NGの場合：受けたFBに対応し、1〜4を繰り返す

全章が1〜5を終えて台帳で「完了」（✅）になったら工程8へ進む。

## 工程8. 全結合（OP/ED結合＋章転換札）
**担当**：creator
オーナー承認済みの全章を、OP/EDと章転換札とともに連結して完成フル版にする。承認済みの実体だけをstream-copyで繋ぎ、再エンコード・all再生成・pick_stock巡回はしない。並び・章転換札・本編BGMなしの仕様と札の寸法/フォントは pipeline.md §9、streamhash手順・スクリプト名は RUNBOOK を読む。
**この工程の完了条件＝同一性・権利・残タスク・法令コンプラの全ゲートをpassした完成フル版が書き出されていること。**

1. 結合前のゲートを通す
- 同一性ゲート：結合入力の各章のstreamhashが承認マニフェストと一致していること
- 権利ゲート：`content-compliance` を発動し、完成物の全素材（OP/EDの映像と音・章転換SE・ナレ音源・フォントを含む）が合法で未確定0件であること
- 残タスクゲート：`TASKS.md` にこの弾の章制作に関わるタスクが0件であること
　failした場合：直ちに修正し、再確認する
　全passするまで結合しない

2. 全章＋OP/ED＋章転換札を連結する
- 並び＝OP→黒gap→第1章（コールド）→章転換札→第2章→…→章転換札→最終章→黒gap→ED
- コールドの直前には章転換札を置かない
- OP/EDは固定資産（4Kアップスケール版）を改変せず、連結はstream-copyのみで行う

3. 結合後を検証する
- 同一性ゲート：完成フル版から各章区間を切り出したstreamhashが承認マニフェストと再一致していること
- 全結合の仕上がり（章転換札の描画・OP/EDのつなぎ・総尺・つなぎ目の黒落ち/音切れ）を実フレームと実音声で確認していること
　failした場合：直ちに修正し、再結合する
　全passしたら工程9へ進む

## 工程9. サムネの作成
**担当**：creator
完成フル版に付けるサムネを、高再生サムネのベンチマークに沿って作り、内部レビューで第一候補を決める。オーナー選定は挟まない（公開前にオーナーが差し替え可能）。作り方は pipeline.md §10、スクリプト名・出力先は RUNBOOK を読む。
**この工程の完了条件＝内部レビューを全passした第一候補サムネが1点決まっていること。**

1. サムネを作る
- 着手前にウェブ調査で同ジャンルの高再生サムネをベンチマークする
- サムネはインパクト重視の短い煽りにする（具体的な答えはタイトル側に回す＝サムネで引き、タイトルがサムネを補足する）
- 実写＋PIL文字で3案作る（10字以内・ダーク基調＋1アクセント・単一被写体・絵文字なし）
- 直近3回公開した動画のサムネと、構成・文言を重複させない

2. 内部レビューで第一候補を決める
→ レビュー：`jinchi-review-thumbnail` を発動する（3案を照合し第一候補を決定する）
　failした場合：直ちに修正し、再発動する
　全passして第一候補が決まったら工程10へ進む

## 工程10. 非公開アップと完了報告
**担当**：creator
第一候補サムネ・タイトル・概要欄が定まった全結合動画を、非公開でアップし、オーナーへ完了報告する。実行値（アップスクリプト・認証トークン名・カテゴリ等）は RUNBOOK を読む。
**この工程の完了条件＝メタ最終確認をpassした全結合動画のアップ処理を実行して正常に動いていることを確認し、オーナーへ完了報告が届いていること。**（アップ完了までは待たない。アップ後のオーナーによる最終確認・公開はオーナー作業＝ここでは起票せず待たない。）

1. タイトルと概要欄を作る
- タイトルはサムネを補足する具体的な煽り文にする（サムネで引き、タイトルで具体化する関係）
- 概要欄に目次（0:00…）とAI明示の免責を入れる
- 目次はtimeline.jsonの実尺から作る（旧版の目次を流用しない）

2. アップ直前メタを最終確認する
- 目次がtimeline.jsonの実尺と一致していること
- アップに渡すVIDEO/THUMBのパスが最終版であること
- containsSyntheticMedia=True・privacy=private・defaultLanguage=ja が設定されていること
- `pm/review-baseline.md` を1回当てて全passであること
　failした場合：直ちに修正し、再確認する
　全passするまでアップしない

3. 非公開アップを実行して報告する
- 全結合動画の非公開アップ処理を実行する（題材ごとにVIDEO/THUMB/TITLE/DESCRIPTION/TAGS/目次を差し替える）
- アップ処理がエラーなく正常に動いていることを確認する（アップ完了までは待たない）
- オーナーへ完了報告する
- アップ後のオーナーによる最終確認・公開はオーナー作業＝ここでは起票せず待たない
