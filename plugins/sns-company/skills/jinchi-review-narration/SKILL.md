# jinchi-review-narration（工程4 ナレーションの成果物レビュー）

人智の外側 長尺パイプラインの **工程4（ナレーション生成）** で、連結ナレ音声をゲートする成果物レビュー。親 `jinchi-longform` の工程4末尾から発動。

## 読むのは3つだけ（混在禁止・token効率）
- ① 本skill内の観点リスト＝工程4の合格ライン
- ② `.company/pm/review-baseline.md`＝全レビュー普遍の項目。権利・合法性は content-compliance 発動で確認する
- ③ `.company/sns_accounts/youtube_ainsight.md`＝人智の外側の戦略・トーン前提の照合先

## フロー（発動＝この順で全実行・fail-closed）
- ① 本skillの観点を成果物（連結ナレ音声）に1つずつ照合し、pass/failを判定する
- ② `pm/review-baseline.md` の各項目を1つずつ照合する
- ③ fail-closed＝1つでもfailなら提出せず修正して①へ戻る
- ④ 全passのみ次の手順へ進める

## 工程4の観点（1つずつ照合）
- [ ] **全章を正規化してから連結し、章境の音量差が無いこと**
- [ ] **誤読の修正が、全再生成でなく該当文のスプライスで行われていること**
- [ ] **台本の語が音声から脱落・置換されておらず、読みモーラの逐語突合で全章の不一致が0件であること**
  - 判定は読み（モーラ）で行い、同音異字・算用数字化などの表記ゆれは不合格にしない。
  - 読了率・カバレッジ率・文字数比などの集計指標を合格根拠にしない。
  - 助数詞・接頭辞・漢数字・単位・専門用語・固有名は語ごとに個別照合し、脱落だけでなく置換も見る。
- [ ] **ピッチ統一をせず、自然ピッチの良いテイクを使っていること**
- [ ] **表示字幕を変えず、TTS入力だけをかな化していること**
- [ ] **テイクにスタイル指示文の音声化が無いこと**
  - 冒頭数秒への混入と、テイク全体がスタイル文言へ置換される破損の両方を確認する。
  - 章の実尺が設計尺から±50%超、またはWhisper全文が台本本文と一致しない場合は破損＝テイクを破棄して再生成する。
  - mp3の存在を「生成完了」の根拠にしない。
- [ ] **冒頭スタイル漏れの修正が、rerollでなくpreamble-trim手順で行われていること**
- [ ] **同一表記の分数・比率が、登場箇所ごとに桁読みへ化けていないこと**
- [ ] **差し替えたテイクの尺が、旧テイクと概ね一致していること**

## 原則
- レビューに出す成果物は、既知の改善余地がゼロで自分で直せる弱点が残っていないこと。
- 要件未達は自分で不合格にして作り直すこと。
- passした成果物だけを提示すること。
