# jinchi-review-caption（工程7 字幕同期の成果物レビュー）

人智の外側 長尺パイプラインの **工程7（章ごとの完成）** で、字幕を同期した章動画をゲートする成果物レビュー。親 `jinchi-longform` の工程7から発動する。

## 読むのは3つだけ（混在禁止・token効率）
- ① 本skill内の観点リスト＝工程7の字幕同期の合格ライン
- ② `.company/pm/review-baseline.md`＝全レビュー普遍の項目。権利・合法性は content-compliance 発動で確認する
- ③ `.company/sns_accounts/youtube_ainsight.md`＝人智の外側の戦略・表記前提の照合先

## フロー（発動＝この順で全実行・fail-closed）
- ① 本skillの観点を成果物に1つずつ照合し、pass/failを判定する
- ② `pm/review-baseline.md` の各項目を1つずつ照合する。権利・合法性は content-compliance 発動でfail-closedとする
- ③ fail-closed＝1つでもfailなら提出せず修正して①へ戻る
- ④ 全passのみ次の手順へ進める

## 検証は必ず実書き出しmp4の実体で行うこと
- 焼き込まれた字幕PNGの実描画を実mp4のフレーム抽出で確認し、音声を抽出してWhisperで再解析し実発話と突き合わせること。captions.json・timeline.json の数値同士の突合や機械ゲートのPASSだけを合格根拠にしないこと。
- 本レビューは制作役が実施し、秘書は代替しないこと。

## 制作順序＝字幕同期は章ごとに回すこと
- 章ごとに独立クリップを書き出して章単位で判定し、不合格章だけ再レンダして、その章がpassするまで直すこと。通しの全結合は工程8で行う。

## 工程7字幕同期の観点（1つずつ照合）
- [ ] **各札の字幕表示開始が、対応する台本行の実発話onsetから基準値以内に収まっていること**
- [ ] **行頭onsetアンカーが成立せず比例配置補間へ落ちた字幕行が、全章で0件であること**
- [ ] **行頭特徴語の行内重複により誤ったonsetへアンカーされた字幕行が、全章で0件であること**
- [ ] **字幕表示開始を、累積文字数比例でなく行頭onsetアンカーで決定する実装であること**
- [ ] **台本の正式表記と字幕を全文差分して、字幕側だけがかな表記のままの箇所が、全章で0件であること**
- [ ] **位取り数と日付の漢数字が、字幕で算用数字へ統一されていること**
- [ ] **概数・単独一桁・助数詞・日付でない語の漢数字が、字幕で原表記のまま維持されていること**
- [ ] **TTSの間を生成するために挿入された読点が、字幕に0件であること**
- [ ] **文法上必要な読点が、字幕に保持されていること**
- [ ] **折り返し後の実描画行数が、字幕1枚あたり2行以内であること**
- [ ] **字幕がPIL PNGのoverlayで白文字黒フチに焼かれていること**
- [ ] **辞書更新後に再ビルドした章の実フレームで、字幕が正式表記に描画されていること**

## 原則
- レビューに出す成果物は、既知の改善余地がゼロで自分で直せる弱点が残っていないこと。
- 要件未達は自分で不合格にして作り直すこと。
- passした成果物だけを提示すること。
