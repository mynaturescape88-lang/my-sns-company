# jinchi-review-script（工程2 台本＋FCの成果物レビュー）★最重要

人智の外側 長尺パイプラインの **工程2（台本＋ファクトチェック）** で、台本とFCログをゲートする成果物レビュー。本chの律速・品質の核。親 `jinchi-longform` の工程2末尾から発動。前提＝`content-planning` スキルを実発動済みであること。

## 台本着手前に理解する前提（必読）
- **(A) チャンネルコンセプト**：「人間には解けなかった真実を、AIが解き明かす」＝人の智では及ばない領域にAIが連れて行ってくれた謎の解明を、落ち着いたナレで15分以上・結で答えを言い切る形で体現する。
- **(B) genuine-AI必須条件**：題材は古代ミステリーに限らず最新AI技術も対象だが、AI・機械学習が発見・創出の中核を実際に担っていることが不変の必須条件（題材確定は工程1・台本執筆時もこの前提を外さない）。

## 読むのは3つだけ（混在禁止・token効率）
- ① 本skill内の観点リスト＝工程2の合格ライン
- ② `.company/pm/review-baseline.md`＝全レビュー普遍の項目。権利・合法性は content-compliance 発動で確認する
- ③ `.company/sns_accounts/youtube_ainsight.md`＝人智の外側の戦略・役割・却下レバーの照合先

## フロー（発動＝この順で全実行・fail-closed）
- ① 本skillの観点を成果物（台本＋FCログ）に1つずつ照合し、pass/failを判定する
- ② `pm/review-baseline.md` の各項目を1つずつ照合する
- ③ fail-closed＝1つでもfailなら提出せず修正して①へ戻る
- ④ 全passのみ次の手順へ進める

## 工程2の観点（1つずつ照合）
- [ ] **結で具体的な答え・到達点を言い切っていること**
- [ ] **起承転結の章立てになっていること**
- [ ] **FCログが台本末尾にあり、数字・年代・固有名詞を一次情報で裏取りしていること**
- [ ] **数字がかな・漢字表記になっていること**
- [ ] **ナレ字数が15分相当以上（約4,400字以上）であること**
- [ ] **台本が即興でなくcontent-planningの実証済み手順で書かれていること**
- [ ] **落ち着いた語り・世界観・FCがあり、AI放置量産になっていないこと**
- [ ] **固有名詞を肩書・逸話等で立ててから導入していること**
- [ ] **同一論点の反復・情緒的な足踏みが3文以上続いていないこと**
- [ ] **主要数値が独立した短文で主役化されていること**
- [ ] **各章末に次章への引きが1文あること**
- [ ] **主役級人物3〜4名が複数回再登場していること**
- [ ] **実在の人物/組織/事件/最新技術を扱う回で、事実・主張・噂を峻別していること**
  - 事実は断定、外部独立検証できない発表値は「〜によれば」と発表時点つきで帰属、噂は「これは噂ですが」と前置きしてから事実で正す。
- [ ] **専門用語を日常の比喩に落とし、前提知識を仮定せず基礎から噛み砕いていること**
- [ ] **カット指定が工程5の取得元リスト内で成立し、無料実写で埋めず0cr図解・合成で表現していること**
- [ ] **制作用の章記号・構成用語（起1・承2・コールドオープン等）が視聴者向け本文に0件であること**
- [ ] **中心比喩が直近3本の動画と重複していないこと**
- [ ] **前作台本の定型句・言い回しをそのまま流用していないこと**
- [ ] **コールドオープンで何についての動画かが伝わること**
- [ ] **コールドオープンで最後まで見ると何を知れるかの要旨予告があること**
- [ ] **コールドオープンが具体的な答え・オチをネタバレしていないこと**
- [ ] **新規に書いた程度・数値の表現が最良ケースの誇張になっていないこと**

## 原則
- レビューに出す成果物は、既知の改善余地がゼロで自分で直せる弱点が残っていないこと。
- 要件未達は自分で不合格にして作り直すこと。
- passした成果物だけを提示すること。
