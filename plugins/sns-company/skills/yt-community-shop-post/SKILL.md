作業の目的：**書くことではない。**廃止するブログが持っていた「検索の入口」を、Googleにインデックスされる `youtube.com/post/<id>` へ移し、①検索で見つかり ②最後まで読まれ ③対象動画が再生される 原稿を作ること。この3つを満たさない原稿は、字数・体裁が正しくても不合格。

**担当**：工程1〜6は creator。工程7は PM。
**成果物の置き場**＝`.company/creator/work/yt-community/<slug>/`（`<slug>`＝WP記事のslug）。

## 前提となる媒体仕様（変更禁止・毎回この前提で設計する）
- コミュニティ投稿は `youtube.com/post/<id>` の独立URLでインデックスされる。**本文にしか存在しない語句で検索すると1〜2位に出る（実測確認済み）**＝本文テキストが検索の入口。
- 本文中のURLはクリック可能なリンクになる。
- 画像は最大10枚。
- **APIで作成できない。下書き・限定公開も無い。**公開設定は公開／メンバー限定／レベル限定の3択。よって**投稿はオーナーの手動操作のみ**＝creatorの成果物は「原稿＋画像」まで。「投稿していません」ではなく「投稿手段が無い」と報告する。

## 工程1. 前提情報の確認
以下が揃うまで着手しない。揃わない項目はオーナーへ確認する。

| 項目 | 例 |
|---|---|
| WP記事ID | 926 |
| 対象チャンネル | @mynaturescape |
| 掲載する動画ID | 4PnTeKIyyvo |
| 動画が1本に確定しているか | 台帳 `seo_growth/channel_video_ledger.csv` を店名でgrepし全数確認 |

動画が複数ヒットした場合は本数と候補をオーナーへ提示し、どれを載せるか確認する（勝手に1本選ばない）。

## 工程2. 元記事の取得（GETのみ・書き込み厳禁）

```bash
WP_PASS=$(grep -E '^WP_PASSWORD=' .env.local | sed 's/^WP_PASSWORD=//' | tr -d '"'"'"'')
python3 - "$WP_PASS" <<'PY'
import sys, json, base64, urllib.request
pw = sys.argv[1]; POST_ID = "926"   # ← 対象のWP記事IDに置き換える
req = urllib.request.Request(f"https://mynaturescape-event.com/wp-json/wp/v2/posts/{POST_ID}?context=edit")
req.add_header("Authorization", "Basic " + base64.b64encode(f"mynaturescape:{pw}".encode()).decode())
req.add_header("User-Agent", "Mozilla/5.0")
d = json.load(urllib.request.urlopen(req))
print("TITLE:", d["title"]["raw"]); print("SLUG:", d["slug"]); print("DATE:", d["date"])
print("=====BODY====="); print(d["content"]["raw"])
PY
```

本文冒頭の `訪問日：` `所在地：` 行を**逐語で控える**（工程4で改変せず使う）。

## 工程3. 検索設計（本文を書く前に必ずここを確定する）

**この工程を飛ばした原稿は不合格。**元記事・依頼書に実在する語だけを使い、以下を確定して表にする。

1. **主キーワード**＝店名フル表記（本文にしか存在しない語句＝1〜2位を取る語）
2. **地域キーワード**＝市区町村名＋施設名/地名（住所行から取る）
3. **カテゴリキーワード**＝元記事本文にある一般名詞（観葉植物／草花／鉢／ガーデニング雑貨／寄せ植え／ハンギング／カフェ 等）

**出現回数の下限（工程6で機械検査する）**

| 語 | 最低出現回数 | 配置 |
|---|---|---|
| 店名フル | **3回** | ①1行目のタイトル ②冒頭の1文 ③本文中盤 |
| 地域キーワード（市区町村） | **2回** | 所在地行＋冒頭の1文 |
| 地域キーワード（施設名/地名） | **2回** | 所在地行＋冒頭または末尾 |
| カテゴリキーワード | 各1回以上 | 本文中に自然に |

> **新語の追加は禁止。**元記事・依頼書に無い地名・施設名・キャッチコピーを検索目的で足さない。

## 工程4. 本文の執筆

### 構成（順序固定）
| 順 | 要素 | 規則 |
|---|---|---|
| 1 | ブログ記事と同じタイトル | **改変禁止**（英字表記もそのまま） |
| 2 | `訪問日：YYYY.M.D` | 元記事から逐語 |
| 3 | `所在地：（番地まで）` | 元記事から逐語 |
| 4 | **冒頭の1文＝フック** | 店名フル＋市区町村＋施設名を1文に収め、かつ元記事の惹句をリライトして掴みにする |
| 5 | 本文 | 見出しなしの一続きの文章 |
| 6 | 締めの1文 | 元記事の「行ってみてください」系を地域キーワード込みでリライト |
| 7 | 動画への導線＋URL | **末尾に1箇所だけ。**動画の尺と、動画でしか得られないものを1文で示す |

> **工程4-4の理由**：コミュニティ投稿はフィード上で数行で折り畳まれる。2〜3行目は訪問日・所在地という事務情報で埋まるため、**その直後の1文が「もっと見る」を押させる唯一の勝負どころ**。ここに検索語と掴みを同居させる。

### 文章のルール
- **リライトである。オリジナル文章の創作は禁止。**新しい情報・新しい主張・新しいキャッチコピーを足さない。Web調査もしない。
- **見出しを使わない。**投稿に見出し機能が無いため、ブログのh2/h3は成立しない。`【】■◆▼●★` 等の見出し記号も使わない。
- セクションの切れ目は接続の文で繋ぐ（例：「飾り方を思い描きはじめると、次に気になるのは器のほうです」）。
- 段落を短く切り、段落間に空行を入れる。**1段落120字以内**を目安にする。
- **サマリー版**＝元記事の**35〜50%**の字数に収める（全文移植は不合格）。
- **です・ます調を単調に連続させない。**体言止め・過去形・問いかけ・感嘆を織り交ぜ、**非です・ます文末を30%以上**にする。

### 書いてはいけない内容
- 一次情報（10年前でも今でも通じる事実だけで書く）
- 価格、および「安い／高い／最安値」等の価格の良し悪しの表現
- 営業時間・定休日・電話番号・予約方法
- 季節・カレンダー性のある表現（「今シーズン」「今春」「初夏から夏にかけて」等）
- **採用写真のファイル名に無い植物名**（品種名・学名は一切書かない。「大型観葉」「小型」「ハンギング」「羽のような細かい葉」等の汎用表現に落とす）
- 根拠のない比較表現（「◯◯としては珍しく」等）
- 楽天ROOMのCTA・アフィリエイトリンク（植物カテゴリは成果が実測ゼロ）
- ブログURL（廃止するため）
- PR表記（案件・提供品が無いため不要。**有る場合は付ける**）

## 工程5. 画像の選定

- **元記事の画像をそのまま使う。生成・加工・トリミングは禁止**（並べ替え・番号付けのためのコピーは可）。
- 候補は**全枚数を `Read` ツールで実際に開いて目視する**。推測で判断しない（Claude Vision等の有料APIは使わない。Claude Code内の `Read` は無課金＝これが正規手順）。
- **上限10枚。**除外基準を満たす写真が10枚に満たない場合は**枚数を減らす**。基準に触れる写真を10枚に揃えるために足さない。

### 除外基準（1つでも該当したら不採用）
| # | 基準 |
|---|---|
| 1 | 値札・価格が**判読できる** |
| 2 | 手書き名札・品種名ラベルが**主役**、または品種名が判読できる |
| 3 | 他社ブランドのロゴ・商品が主役 |
| 4 | 季節・年中行事の掲示（母の日ポスター等）が判読できる |

### 並び順
- **タイトルカード（店名テキスト入りの合成画像）は含めない。**実写だけで構成する。
- **1枚目**＝実写のうち最も引きが強く明るいカット（店の全景・入口まわり等）。フィードのサムネイルになる。
- **最終枚**＝本文の締めに対応する写真。
- **同一被写体・同一構図を連続させない。**引き↔寄り、通路↔棚、屋外↔店内を交互に配置し、似た構図は最低1枚離す。
- 本文の記述順と画像順を対応させる。

確定後、投稿順に番号を振ったフォルダへコピーする。

```bash
mkdir -p images_post
cp <pool>/<file> images_post/01_<内容>_wp<ID>.<ext>   # 以下10枚まで
ls images_post | wc -l                                 # 10であること
md5 -q images_post/* | sort | uniq -d | wc -l           # 0であること（重複なし）
```

## 工程6. 機械検査（全て0件でなければ工程7へ進まない）

```bash
F=post_text_final.txt
for p in \
 '円|¥|￥|価格|税込|税抜|安い|高い|お得|最安|リーズナブル|お手頃' \
 '営業時間|定休|電話|TEL|予約|[0-9]{2,4}-[0-9]{2,4}-[0-9]{3,4}' \
 '今シーズン|今春|初夏|春|夏|秋|冬|季節|旬|セール|フェア|母の日|GW' \
 'mynaturescape-event|wp-content' \
 'room\.rakuten|楽天|ROOM|アフィリ' \
 'PR|ＰＲ|広告|プロモーション|案件' \
 '【|】|■|◆|▼|●|★|##|<h[1-6]' \
 '珍しく|一番|最も|No\.1|日本一|他店' \
 '効果|効能|癒し|健康|ストレス|空気清浄|症状' ; do
  printf "%s : %s件\n" "${p:0:24}" "$(grep -cE "$p" $F)"
done
# 採用写真のファイル名に無い植物名（工程3で列挙した固有名を並べる）
grep -cE 'エバーフレッシュ|ユッカ|ロストラータ|エアプランツ|チランジア|エスキナンサス|ポトス|エピフィラム' $F
grep -c 'https\?://' $F   # 1（動画リンクのみ）であること
```

続けて**目的の達成度**を数値で検査する。下限を割ったら工程4へ戻す。

```bash
python3 - <<'PY'
import re
t = open("post_text_final.txt", encoding="utf-8").read()
print("字数(空白除去):", len(re.sub(r"\s", "", t)))       # 元記事の35〜50%
for kw in ["<店名フル>", "<市区町村>", "<施設名/地名>"]:    # 工程3の表で置換
    print(kw, t.count(kw), "回")                          # 順に 3/2/2 以上
ends = [s.strip() for l in t.split("\n") if l.strip() for s in re.split(r"(?<=[。！])", l) if s.strip()]
masu = sum(1 for e in ends if re.search(r"(ます。|です。|ますね。|ました。|ません。|ますね！|ください！)$", e))
print(f"非です・ます {(len(ends)-masu)*100//len(ends)}%")   # 30%以上
print("最長段落:", max(len(p.replace("\n","")) for p in t.split("\n\n") if p.strip()))  # 120字以内
PY
```

## 工程7. レビュー（PM担当・fail-closed）
1. `content-compliance` スキルを**実際に発動**する（景表法／薬機法／ステマ／著作権／事実／日本語／安全性）。
2. `.company/pm/review-baseline.md` の各項目に照合する。
3. `.company/fb/shop-article.md` の各項目に照合する（写真ルール・断定禁止・文末リズムは本タスクにも適用される）。
4. `.company/sns_accounts/youtube.md` の戦略と相違が無いか確認する（却下レバー＝投稿頻度増／サムネ変更／タイトル変更／既存公開長尺の概要欄改変 に触れていないこと）。

- **各項目のpass根拠は、成果物からの逐語引用または実測数値で示す。**「全pass」の総括だけは不可。
- 1項目でもfailなら修正し、該当スキルを再発動する。全passするまで提出しない。

## 工程8. 台帳へ記録
`.company/creator/work/yt-community/POSTS.md` に1行追記する。同じWP記事IDの行が既にあれば**二重投稿**なので着手前に止める。

| 列 | 内容 |
|---|---|
| WP記事ID / slug | 元記事の特定 |
| 店名 | 表示名 |
| 訪問日 | 投稿本文と一致させる |
| 動画ID | 本文末尾のURLと一致させる |
| 原稿パス / 画像パス | 成果物の所在 |
| 状態 | `原稿完成` → オーナー投稿後に `投稿済` |
| 投稿URL | `youtube.com/post/<id>`。**オーナーが手動投稿して初めて確定する**ため、投稿後にオーナーから受け取って記入する |

**1投稿1ショップ。**訪問日は当該ショップの訪問日で一意に決まるため、投稿をまたいだ日付の突き合わせは不要。台帳が担うのは二重投稿の防止と投稿URLの記録のみ。

## 工程9. オーナーへの提示
1. 画像はプレビューHTMLを生成し `open -a "Google Chrome" file://<絶対パス>` で表示する（チャットに一覧を書き出さない）。
2. 報告は結論→根拠で簡潔に。原稿全文・字数・画像の並び順と選定理由・落とした記述と理由・レビュー結果を出す。
3. **「投稿は実行していません」と書かない。**APIが無く投稿手段が存在しないため、「投稿はオーナーの手動操作が必要」と書く。
