# ローカルファイル安全整理スキル

ローカルのファイル/フォルダを「誤削除ゼロ」で整理する。容量回収・重複排除・認証情報の隔離・ワークスペース整理に使う。

## 🔴 最重要原則（常に最優先）

1. **明確に「不要/重複」と判断できない場合は、絶対に削除せず必ずオーナーへ確認する。** 迷ったら消さない。
2. **ファイル名・日付だけで判断しない。必ず中身で確認する**（名前は嘘をつく：ブラウザ連番名・"test"名でも現役、等）。
3. **削除は「ゴミ箱へ移動」。`rm`（完全削除）は使わない。** ゴミ箱を空にするのはオーナーのみ（こちらからは行わない）。
4. **何かを消す前に、同等の控えが残ることを確認する**（ワークスペース内/GitHub/別エクスポート等）。
5. **認証情報・機密データは削除でなく隔離**（後述）。判断に迷う機密は必ずオーナー確認。

## ワークフロー（毎回この順）

1. **候補を探す** … 対象ディレクトリをサイズ・更新日付きで棚卸し（`du -sh`・`stat`）。大物・一時ファイル・重複を洗い出す。
2. **中身で正体を確認** … 下記「確認手法」で実体を特定。
3. **一覧化してオーナーに提示** … 「対象ファイル・正体・削除/保持の根拠・リスク」を表で提示。確度別（確実に不要🟢／要判断🟡／残す🔴）に分ける。
4. **オーナーの承認を得る** … 承認された分だけ進める。1件ずつでも可。
5. **ゴミ箱へ移動** … 移動直前に控えの存在を再確認 → ゴミ箱へ → ゴミ箱内に在ることを確認。

## dry-run提示フォーマット（固定書式・1ファイル1行）

ワークフロー3の一覧提示は、誰がやっても同じ表になるよう次の固定書式で出す。移動候補と削除候補は**別リスト**にし、それぞれ**全件を1ファイル1行で列挙**する（省略・件数制限は禁止）。承認後に**承認された分だけ**実行する。

- **移動候補（1行1ファイル）**＝`<現在の絶対パス> | <移動先の絶対パス> | <分類> | <理由>`
- **削除候補（1行1ファイル）**＝`<絶対パス> | <分類> | <理由> | <進行タスク/運営への影響> | <控えURL(WP/CDN/SNS等)>`

各行の頭に確度ラベル（確実に不要🟢／要判断🟡／残す🔴）を添えてよいが、上記の列構成・列順は変えない。

### 削除候補に入れてはいけないもの（再生成の"種"）

一度失うと再現不可な元素材は**削除候補に載せず** `work/` 内に保全する。具体例＝soul元画像・語り部口パクの元写真・TTS元音声・生成の元にした参照画像・**公開動画のサムネイル画像（ブログ等での再利用素材）**・**MiniMaxクローン用のソース音声（クローンの元音源）**・**Geminiナレーター音声を作るためのコツ／プロンプト／設定（再生成の手順そのもの＝失うと同じ声を再現できない）**。これらは「公開済み」「使い終わった」でも破棄理由にしない。**重複（md5一致）でワークスペース内に控えがあっても、種だけは削除候補に載せない**（他の重複は余剰をゴミ箱化してよいが、種は正本を一元管理して残す）。

## 確認手法（種別ごと・名前に依存しない）

| 種別 | 確認方法 |
|---|---|
| 完全重複か | `md5 -q` でワークスペース/プロジェクト内の同一ファイルと突合（一致＝バイト同一の控えあり→重複） |
| 画像 | 実際に開いて目視照合（再エンコードでmd5は不一致になる。名前も移行時に変わる） |
| zip等アーカイブ | `unzip -l` で中身一覧を展開フォルダと比較。展開済みなら zip は重複 |
| アプリのdmg/インストーラ | `/Applications` に導入済みか確認。導入済みなら不要（再DL可） |
| 旧ワークスペース/リポジトリ | GitHub remote を確認。push済み(0 unpushed)=踏襲済み→重複。**アーカイブ済みrepoは一時解除→退避ブランチへpush→再アーカイブ**してから削除 |
| キャッシュ/venv/ビルド成果物 | 再生成可能(`pip install`・波形.pfl・`__pycache__`等)=安全。ただし何のプロジェクトのものか確認 |
| **現役データ（最重要の罠）** | **「古そう」でも中身ファイルの更新日(mtime)を必ず確認。** 親フォルダが古くても中に最新データがあることがある（例：DaVinci ProjectのライブDBがバックアップ風フォルダ内にあった） |
| スクリプト/task_log/作業フォルダが参照するファイル | 移動/削除前に `grep -rl "ファイル名"` でコード・task_log・議事メモの参照を確認。現役参照があれば**動かさない**か、動かすなら参照側のパスも同時に張り替える（稼働スクリプトの作業ディレクトリ・THUMBの直参照・承認サンプルのtask_logパス等。"test"風の名前でも現役でありうる） |
| アプリが内部管理するデータ（成果物でない） | 動画編集アプリ等が自動生成・管理するフォルダ（DaVinci Resolveの `.gallery`/`Resolve Project Backups`/`CacheClip`/`ProxyMedia` 等）は「成果物/素材」でなくアプリ内部物＝**移動/削除しない**（誤移動でアプリのプロジェクト参照が切れる）。キャッシュと違い手動での再生成対象でもない |
| 同名だがmd5が違う「双子」（二重バックアップ等） | ファイルサイズやsipsのヘッダ検査では壊れを見抜けない。**PILで`im.load()`（全画素デコード）を試し、成功する方が正しい実体・失敗（truncated）する方が破損**。壊れていない方だけを採用する |

## 判断ルール（重複か否か）

- **ワークスペースに同等内容がある → ローカル(Downloads等)のは一時コピー＝削除（要承認）**
- **ワークスペースに無い → 役目があるならワークスペースへ移動して保管。役目終了か不明なら確認**
- **「タスクはワークスペース内の情報で完結している」前提**。Downloads等の作業ファイルは一時的なものが多い。ただし**断定できない時は確認**。
- **用途／紐づくタスクを特定できない → 憶測で特定タスクのフォルダ（確定の行先）に入れない。** 暫定集約用のinbox（例：`.company/creator/work/_inbox-downloads/…`）へ寄せるか、要オーナー確認に回す（誤った確定移動は後で正しい場所を探す手間を生む・最終振り分けはオーナー）。
- **二重バックアップ（コピーA/コピーBのようにほぼ全体がミラーだが由来が別）は「どちらかをmasterに決めて丸ごと削除」しない**。両者が完全な部分集合関係とは限らず、それぞれにしか無いユニークファイルが混じっていることがある。**個々にmd5一致を実証できた分だけ**片方から削除し、両側の固有ファイルは必ずunionで残す（丸ごと削除は実証してから）。

## 認証情報・機密データの扱い

- **APIキー・サービスアカウント鍵・OAuthシークレット(`private_key`/`client_secret`含むjson)・`.env`・`*.key`/`*.pem`** は削除しない。
- **リポジトリ外の専用ディレクトリ（例：`~/credentials/`・権限700）へ移動**して隔離。`plant-blog-bots/secrets/`等リポジトリ内は不可（gitミスで流出・Privateでもサーバー保存/履歴残存リスク）。
- 移動したら**参照スクリプトのパスを更新**し、動作確認（新パスが実在ファイルを指す・構文OK・古い参照が残らない）。
- **健康/個人データ等の機密性は案件ごとに判断**。GitHubに上げてよいかはオーナーに確認（オーナーが「非機密」と明言すればPrivateリポジトリ保存可）。

## ゴミ箱へ移動するコマンド（rm禁止）

```bash
osascript -e 'tell application "Finder" to delete POSIX file "/絶対パス"'
# 複数はループで。移動後に ~/.Trash に在ることを確認する。
```

**ゴミ箱内の存在確認が詰まる場合**：`~/.Trash`はTCCでshellから`ls`/`find`できないことがある（黙って0件を返す＝誤って「消えた」と誤判定しやすい）。また `osascript` で `every item of trash whose name starts with ...` のような全件走査は、ゴミ箱が大きいとタイムアウトする。**個別ファイル名を指定した `exists item "<name>" of trash` で1件ずつ確認**するのが確実（大量件数は移動前後の総数デルタ＝`count of items of trash`の差分でも検証できる）。

## 危険な移送/削除時の原本退避（archive/ ＝凍結アーカイブ）

- **移送・大規模整理・削除など後戻りしづらい危険操作の際は、原本を削除でなく凍結アーカイブ（`archive/`）へ一時退避する**（後戻り可能を担保）。これは常設の退役置き場（`使用後/` のような常設フォルダ）ではなく、**移送等の危険操作で原本を失わないための一時退避**であり、操作の妥当性を確認できたら不要な退避分はゴミ箱へ回す。
- 退避後、参照側（スクリプト・task_log・議事メモ）のパスが原本を指したままになっていないか `grep -rl` で確認し、必要なら張り替える。

## よくある罠（このスキルが防ぐ失敗）

- ブラウザのダウンロード連番名（`CLOVER (1).png` が実は別店のサムネ）→ **必ず開いて中身確認**
- `test01`・`Untitled`・"old"風の名前でも**現役で使用中**のことがある → 使用状況・更新日を確認
- バックアップ風フォルダに**最新の現役データ**が入っていることがある → 中の更新日を確認
- スクリプトが**Downloads直下の絶対パス**で認証情報を直参照していることがある → grepで確認

## 完了時

- 何を削除/移動/保持したかを表で報告。回収容量と、ゴミ箱を空にすれば実容量が戻ること（空にするのはオーナー）を伝える。
- 今後のために、確立した方針（誤削除防止・確認前提）を踏襲する。
